# Рост канала: подписка, репосты, атрибуция, статистика

Код: `src/investor_agent/growth/`. Данные: те же SQLite `data/investor.sqlite3` (том контейнера, переживает перезапуск).
Отдельного сервиса и n8n в цепочке нет: статью, пост и кнопки делает код бота, поэтому сбор тоже в нём.

**По умолчанию выключено:** включается `GROWTH_ENABLED=1` в `.env`. Откат — убрать переменную и перезапустить.

## Что делается
1. **Статья.** `publish()` до создания Telegraph-страницы вызывает `growth.publish.begin`: строка публикации, личная
   invite-ссылка `telegraph/cta` (createChatInviteLink), блок подписки в конце статьи (утверждённый текст).
2. **Репосты.** Когда URL статьи известен, к последней части статьи добавляется «Поделиться разбором» (Telegram, VK,
   WhatsApp; editPage, URL не меняется). Идемпотентно: перед правкой страница читается (getPage), дубль не создаётся;
   при сбое Telegraph планировщик повторяет каждые 5 минут. Текст репоста: «Компания: подзаголовок статьи».
3. **Пост.** После отправки добавляется вторая кнопка «📤 Отправить другу» (t.me/share/url на сам пост канала); id поста
   сохраняется. Кнопка «Читать разбор» остаётся.
4. **Атрибуция подписок.** Бот администратор канала, webhook нет, поэтому `getUpdates(allowed_updates=[chat_member])`
   каждые 5 минут (offset в БД, дедупликация по `update_id`). Вступление по нашей invite-ссылке → источник ссылки;
   вступление без ссылки, по чужой ссылке и любая отписка → `UNKNOWN` (Telegram не сообщает источник отписки).
   Открытие ссылки подпиской не считается.
5. **Другие источники.** `python -m investor_agent growth-link --source youtube --date YYYY-MM-DD` печатает отдельную
   invite-ссылку (instagram, tiktok, youtube, vk, whatsapp, other) для описания видео/профиля.
6. **Статистика (ежедневно 08:00 Пекин).** Telegraph getViews (ежедневно для выпусков до 14 дней, потом раз в неделю),
   число подписчиков (Bot API getChatMemberCount), TGStat channels/stat (1 запрос в сутки), затем краткий отчёт
   админу в личный чат (`TELEGRAM_ADMIN_CHAT_ID`, не в канал). Экспорт: `growth-export --out DIR` (CSV+JSON).

## Таблицы
`publications`, `tracking_links` (уникально publication+source+medium; `invite_link`, `code`), `traffic_events`,
`subscription_events` (оба с уникальным `event_deduplication_key`), `metric_snapshots` (PK provider+publication+source+
metric+время; publication 0 = канал целиком), `provider_status` (последняя ошибка, пауза, счётчик запросов месяца).
Снимки не перезаписываются и не удаляются; недоступный источник пишет ошибку и оставляет старые данные.

## TGStat FREE
Только `channels/stat` (STAT API). Лимит 50/мес, свой резерв `TGSTAT_RESERVE=5`: автоматические запросы
останавливаются на 45. Запрос считается до отправки. 402/429 — пауза до 1-го числа, 401/403 — 3 суток, прочее — сутки.
После `TGSTAT_ACCESS_UNTIL` (2026-12-07) опрос выключается сам, отчёт пишет «доступ закончился». Устаревшими считаются
данные старше 48 часов.

## Клики (`/go/<code>`)
Эндпоинт реализован (302 только на сохранённые цели с хостов t.me, telegram.me, telegra.ph; боты/превью пишутся как
`bot_click`; в БД только дневной солёный хэш, IP/UA не хранятся). Включается переменной `PUBLIC_BASE_URL`; IP берётся из X-Forwarded-For только при `TRUST_PROXY=1`, не больше 2000 записей кликов на ссылку в сутки; без неё ссылки
ведут напрямую, а в отчёте «переходы не измеряются». Контейнер слушает только 127.0.0.1:8010, нужен публичный HTTPS
(обратный прокси/туннель на `/go/*`).

## Ограничения
- Telegram не отдаёт клики по invite-ссылкам и источник отписок; просмотры поста Bot API не даёт (TGStat posts стоит
  отдельных запросов и не используется).
- Telegraph getViews — общие просмотры первой части, не уникальные читатели и не по источникам; UTM в ссылках для
  репостов нужны только внешней аналитике.
- Общий прирост ≠ сумма источников: в отчёте они разделены.

## Публикация и сбои (состояние `unicorn_publish_state:<дата>`)
Состояния: пусто → `sending` (записано перед вызовом Telegram) → `sent:<id>` (пост доставлен, id сохранён) → после
всех шагов «опубликовано» пишется последним и состояние очищается. `requires_manual_reconcile` — доставка неизвестна.

| Где оборвалось | Что происходит |
|---|---|
| после `sent:<id>`, до «published» | повтор не шлёт пост, доделывает архив, опрос, кнопки, глоссарий (все шаги идемпотентны), затем «published» |
| ответ Telegram не получен (таймаут, потеря связи, 5xx; `TelegramError.ambiguous`) | `requires_manual_reconcile`, повторов нет, текстового пост-дубля вместо фото нет, админу сообщение |
| после `sending`, до вызова Telegram (процесс убит) | то же: `requires_manual_reconcile`, выпуск не «published», архив/опрос/глоссарий не выполняются |
| отказ Telegram (ok=false, HTTP 4xx) | состояние снимается, повтор безопасен |
| после createPage, до `page_url` | повтор ищет страницу по точному названию (`getPageList`) и использует её |
| поиск страницы упал или нашёл несколько | createPage не вызывается, публикация «failed», повтор позже; при дублях названий нужна ручная проверка |

Продолжение после проверки канала: `python -m investor_agent reconcile --date YYYY-MM-DD --message-id <id>` (пост
есть: выпуск завершается с этим id) или `--not-sent` (поста нет: следующий publish отправит его).
При настроенном webhook вступления не собираются: бот сообщает админу раз в сутки и webhook не трогает.
